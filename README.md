# Waste Classifier

Image classification models for the RealWaste dataset.

## Datasets

The datasets are hosted externally and are not included in this repository.

| Dataset | Source |
|---|---|
| Dataset 1 | [Pictures of Simple Electronic Components](https://www.kaggle.com/datasets/divyejoshi/pictures-of-simple-electronic-components) |
| Dataset 2 | [Electronic Components](https://www.kaggle.com/datasets/aryaminus/electronic-components) |
| Dataset 3 | [Microorganism Image Classification](https://www.kaggle.com/datasets/mdwaquarazam/microorganism-image-classification) |
| Dataset 4 | [Textures Dataset](https://www.kaggle.com/datasets/roustoumabdelmoula/textures-dataset) |
| Dataset 5 | [ASL Dataset](https://www.kaggle.com/datasets/ayuraj/asl-dataset) |
| Dataset 6 | [RealWaste](https://archive.ics.uci.edu/dataset/908/realwaste) |

Place the RealWaste class folders under `dataset6/`.

## Training

Each command trains one optimizer only. The `--optimizer` argument is required.

```powershell
python modelA.py --optimizer adam
python modelB.py --optimizer adam
```

Available optimizer keys are `adam`, `adam_1e-3`, `sgd`, `sgd_m0.5`, and
`sgd_m0.9`. Additional options include `--epochs`, `--batch-size`, `--seed`,
`--dataset`, and `--aug`.

Model A also accepts `--arch base` or `--arch deep`.

## Results

Results are separated by model and optimizer:

```text
results/
  modelA/
    adam/
    sgd/
  modelB/
    adam/
    sgd/
```

Every optimizer folder contains the trained `model.keras`, `metrics.json`,
`training_history.json`, `classification_report.txt`, `run_metadata.json`,
`command.txt`, architecture reports, training curves, class distribution plot,
and `confusion_matrix.png` plus `confusion_matrix.csv`. Model B also records
its parameter-limit check.

Run the desired optimizer separately to populate each optimizer folder; no
optimizer comparison or interpretation report is generated by either model
script.

## Comparing saved results

After training one or more optimizers for both models, run:

```powershell
python compare.py
```

The script discovers every saved optimizer folder under `results/modelA/` and
`results/modelB/`. Each saved run gets its own column, such as
`modelA_adam`, `modelA_sgd`, or `modelB_sgd_m0.9`. Missing runs are omitted
from the report; missing metric values are shown as `N/A`. It writes:

- `results/comparison_table.md`: readable table with one column per saved run
- `results/comparison_table.csv`: one row per saved model and optimizer run
- `results/comparison_table.json`: full loaded metrics

To use another results directory:

```powershell
python compare.py --results-dir path\to\results
```
